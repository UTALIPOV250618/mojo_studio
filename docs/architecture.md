# Той Студия — архитектура MVP

> Источник требований: дизайн-система «Той Студия» (claude.ai/artifact/CL1yyrtm3XzrovRgnNQRxw) — `README.md`, `screens.md`, 14 компонентов, `tokens.json`.
> Дата: 2026-11-06, правки по итогам фазы 0 — 2026-11-08 ([`docs/spikes/phase0-decisions.md`](spikes/phase0-decisions.md)). Статус: черновик для ревью.
> Исходная схема идеи: [`toy-video-mvp-architecture.svg`](../toy-video-mvp-architecture.svg). Этот документ её детализирует и не противоречит ей.

## 0. Решения коротко

1. **Настольное приложение на Python 3.12 + PySide6 (Qt 6.8+)**, только Windows 10/11 x64. Интерфейс в одном процессе, вся тяжёлая работа — в **отдельных процессах-исполнителях** (worker), которые запускает `QProcess`. Интерфейс никогда не зависает, а падение анализа не роняет приложение.
2. **Одно декодирование на файл.** Один запуск ffmpeg даёт сразу три выхода: копию для анализа 540 по короткой стороне (proxy: 960×540 или 540×960), звук 16 кГц моно для распознавания речи, кадры 160×90 с частотой 4 к/с для метрик кадра. Узкое место — декодирование исходников 1080p/4K, и мы проходим его ровно один раз (S3: Python и pipe ffmpeg не тормозят; декодирование по умолчанию на CPU).
3. **Распознавание речи — за интерфейсом `SpeechRecognizer`**, модель выбираем по результатам спайка S1. Кыргызский — главный технический риск (§2).
4. **Моменты собираются локально и без сети**, правилами из сигналов: речь, аплодисменты и музыка (YAMNet), движение, качество кадра. Облако моменты не ищет.
5. **План монтажа составляет облачная модель (Claude) через наш собственный сервер** (`plan-service`). Ключ API никогда не попадает в клиент. Отправляем только текст: таблицу моментов и задание. Ответ — строгий JSON по схеме. Дальше его **детерминированно** проверяет и подгоняет локальный «фиттер».
6. **Плеер редактора — libmpv (LGPL-сборка)** через render API в `QOpenGLWidget`, со списком отрезков в формате `edl://` поверх proxy-файлов (S2). Все proxy имеют одинаковые параметры кодека, а это требование EDL для бесшовного воспроизведения. Таймлайн рисуем сами в `QGraphicsView`.
7. **Таймлайн — неизменяемая (immutable) модель в чистом Python без Qt.** Каждая команда — чистая функция `Timeline → Timeline`. Отмена хранит снимки. Пустот на таймлайне нет по построению: позиции вычисляются, а не хранятся.
8. **Экспорт кусками (чанками).** Видео рендерится чанками 30 с (S5) с одинаковыми параметрами кодировщика и склеивается через concat без перекодирования. Звук рендерится **одним непрерывным проходом** и потом сводится с видео. Отсюда возобновление после обрыва («Готовая часть сохранена»), честный прогресс и отсутствие рассинхрона.
9. **Проект — это папка с SQLite** (`project.db`, WAL) и кэшем. Исходные видео не трогаем, пока пользователь сам не выбрал «копировать».
10. **Тема генерируется из `tokens.json`**: `theme_dark.qss`, `theme_light.qss` и `tokens.py`. Тексты на двух языках — через Qt Linguist, язык переключается без перезапуска.

## 1. Анализ требований

### 1.1 Главный сценарий и его бюджет

Монтажёр делает 3–10 тоев в неделю. Цель — клип за **20–30 минут работы человека** вместо нескольких часов. Анализ при этом может идти долго, если человеку не нужно сидеть рядом.

| Шаг | Чьё время | Цель MVP |
| --- | --- | --- |
| Создание проекта и добавление файлов | человек | ≤ 2 мин |
| Анализ 3 ч 40 мин сырья (пример из спецификации) | машина, человек свободен | на эталонном ПК, без учёта ASR: **≤ 30 мин** для 1080p 25/30 к/с (≤ 25 Мбит/с), **≤ 60 мин** для 1080p 50/60 к/с (камеры до 80 Мбит/с), для 4K HEVC — честный ETA и предупреждение до старта. ETA показываем с первой минуты (профиль принят 2026-11-08 по S3, [`phase0-decisions.md`](spikes/phase0-decisions.md)) |
| Отметки и задание | человек | 5–10 мин |
| Сборка черновика (облако) | машина | ≤ 90 с |
| Правка черновика | человек | 10–15 мин |
| Экспорт 5-минутного клипа 1080p | машина | ≤ 3 мин с GPU, ≤ 8 мин на процессоре |

**Эталонный ПК** (фиксируем и покупаем для тестов): 6 ядер / 12 потоков (класс i5-10400), 16 ГБ ОЗУ, SSD плюс HDD с данными, **два варианта** — с GTX 1650/1660 (6 ГБ) и вообще без дискретной видеокарты. 1920×1080 при 100% и 125%.

### 1.2 Нефункциональные требования, выведенные из спецификации

- **Офлайн по умолчанию.** Без сети работает всё, кроме «Собрать черновик» и «Переделать с новым заданием» (§7 экранов). Значит, анализ, модели, шрифты и ffmpeg поставляются вместе с программой, а не скачиваются при первом запуске.
- **Приватность — это обещание в интерфейсе:** «В интернет уходит только текст. Видео остаётся на компьютере». Клиент технически не умеет отправлять в сеть кадры и звук: сетевой модуль принимает только `PlanRequest`. Нарушение этого правила — баг уровня релиза.
- **Слабое и нестабильное соединение.** Запросы маленькие, есть ключ идемпотентности, задание выполняется на сервере асинхронно, клиент его опрашивает. Если связь рвётся посреди ответа, работа не теряется.
- **Долгие процессы переживают закрытие окна и перезапуск.** Каждый этап анализа сохраняет контрольную точку на каждый файл.
- **Отзывчивость:** интерфейс ≤ 16 мс на кадр при работе с таймлайном, прогресс обновляется не чаще 4 раз в секунду, перемотка в плеере ≤ 150 мс.
- **Без технических терминов в интерфейсе.** Коды ошибок показываем только за ссылкой «Подробнее для поддержки».

## 2. Главные риски

| Риск | Вероятность / влияние | Чем снимаем |
| --- | --- | --- |
| **R1. Плохое распознавание кыргызской речи** в шумном зале, с музыкой и смешением с русским. Публичные дообученные модели показывают высокую ошибку: у карточки BuzzASR/kyrgyz (дообучение large-v3) WER ≈ 43% (CER ≈ 11%) на чистых наборах FLEURS/Common Voice, в зале будет хуже. | высокая / высокое | Спайк S1 на 3 реальных тоях. Стратегия «текст — только один из сигналов»: тост находится и по структуре звука (долгая речь одного голоса → аплодисменты), а моделе-планировщику достаточно «шумной» расшифровки. Ключевые слова — по CER, а не по WER. Опция в настройках: «точная расшифровка» на GPU. |
| R2. Анализ медленнее бюджета на ПК без видеокарты. **S3: подтвердился** — 1080p50 ≈ 52–59 мин, 4K HEVC 10 бит ≈ 5,3 ч на 5600H без ASR; `d3d11va` не быстрее CPU. | высокая / высокое | Одно декодирование (§5.1), детектор речи (VAD) отсекает музыку до распознавания, звук нескольких камер одной сцены распознаём один раз. Честный ETA по битрейту и профиль целей (`phase0-decisions.md`), уведомление: до ~60 мин приемлемо, если человек ушёл. `d3d11va` — только разгрузка CPU под ASR, не ускорение. |
| R3. mpv: бесшовность EDL, встраивание в Qt, лицензия сборки (GPL/LGPL). **S2: снят** — стыки точные, LGPL-сборка есть, render API работает на Mac и Windows. Остаток: пересборка EDL на Windows 0,3–0,55 с, графика Intel не проверена. | низкая / среднее | Разбор пересборки в фазе 4. Запасной план — QtMultimedia (FFmpeg-бэкенд) — не понадобился. |
| R4. Качество плана: модель выбирает не то, путает роли гостей. | средняя / высокое | Детерминированный фиттер и валидатор, обязательные и исключённые моменты как жёсткие ограничения, eval-набор, версионирование промптов на сервере (правим без релиза клиента). |
| R5. Ложные срабатывания антивирусов и SmartScreen на собранном Python-приложении. | высокая / среднее | Подпись кода с первого пилота, сборка onedir, а не onefile. |
| R6. Нет реальных записей для разработки и оценки. | высокая / высокое | Задача фазы 0: 5–10 тоев с письменного согласия, разметка монтажёром (тосты, танцы, выход молодых). Без этого качество нельзя мерить. |

## 3. Архитектура

### 3.1 Контейнеры

```
┌──────────────────────────── ПК монтажёра (Windows) ─────────────────────────────┐
│                                                                                │
│  ToyStudio.exe  (процесс интерфейса, PySide6)                                  │
│   ├─ Экраны и виджеты (app/)  ←→  ViewModel'и  ←→  Сервисы                     │
│   ├─ Плеер: libmpv (render API в QOpenGLWidget)                                │
│   ├─ JobManager ──QProcess──▶ toystudio-worker.exe (анализ / экспорт)          │
│   │                              ├─ ffmpeg.exe / ffprobe.exe (подпроцессы)     │
│   │                              ├─ распознавание речи (CTranslate2 / ONNX)    │
│   │                              └─ YAMNet, OpenCV, детектор сцен             │
│   ├─ PlanClient ─────HTTPS (только текст)──────────────┐                       │
│   └─ Хранилище: <папка проекта>/project.db + cache/    │                       │
│                 %APPDATA%/ToyStudio/app.db             │                       │
└────────────────────────────────────────────────────────│───────────────────────┘
                                                         ▼
                         plan-service (FastAPI, ЕС-регион)
                          ├─ активация лицензии → токен устройства
                          ├─ очередь plan-jobs, ключ идемпотентности
                          ├─ шаблоны промптов с версиями + JSON-схема ответа
                          └─ Claude API (по умолчанию claude-sonnet-5-5)
```

Почему исполнители — отдельные процессы, а не потоки: GIL, нативные библиотеки (CTranslate2, onnxruntime, OpenCV) могут упасть целиком, процесс можно безопасно убить по «Остановить», а приоритет процесса ставим `BELOW_NORMAL`, чтобы компьютер оставался отзывчивым. `QProcess` вместо `multiprocessing` — потому что он встроен в цикл событий Qt и не ломается в собранном (frozen) exe.

### 3.2 Слои и правило зависимостей

```
toystudio/
  core/       чистая логика без Qt и без ввода-вывода: модели, таймлайн, команды, фиттер, валидатор плана
  engine/     анализ и экспорт: ffmpeg, распознавание речи, звуковые события, кадры, моменты, граф экспорта
  storage/    SQLite, миграции, раскладка папки проекта, атомарная запись
  jobs/       протокол исполнителей, JobManager (Qt), точка входа worker'а
  cloud/      PlanClient, офлайн-очередь, монитор сети
  app/        Qt: оболочка, экраны, виджеты, таймлайн, плеер, тема, i18n
server/       plan-service (отдельный пакет, деплоится отдельно)
tools/        gen_theme.py, бенчмарки, конвертация моделей
design/       tokens.json (копия из дизайн-системы)
```

Правило: `core` не импортирует ничего из проекта; `engine`, `storage` и `cloud` импортируют только `core`; `jobs` импортирует `engine`, `storage` и `core`; `app` может импортировать всё. Правило проверяем тестом на импорты (import-linter). Благодаря этому вся логика монтажа тестируется без Qt и без видео.

### 3.3 Взаимодействие интерфейса и сервисов

MVVM без фреймворка: экран (QWidget) подписан на сигналы ViewModel (QObject), а ViewModel вызывает сервисы.

| Сервис | Отвечает за |
| --- | --- |
| `ProjectService` | проекты, варианты (Cut), файлы, место на диске |
| `AnalysisService` | запуск и возобновление анализа через JobManager, ETA, уведомления |
| `MomentService` | лента моментов, фильтры, отметки ★/⊖, правка расшифровки |
| `PlanService` | сборка `PlanRequest`, офлайн-очередь, применение плана через фиттер |
| `EditorController` | текущий Timeline, History, автосохранение, выделение, связь с плеером |
| `ExportService` | пресеты, обнаружение GPU, чанковый экспорт, возобновление |
| `Connectivity` | `QNetworkInformation` плюс проверка `/health` сервера раз в 30 с |

Миграции — пронумерованные SQL-файлы и `PRAGMA user_version`. Перед миграцией копия `project.db.bak`.

## 5. Конвейер анализа

### 5.1 Этапы

| # | Этап (интерфейс) | Внутри | Выход |
| --- | --- | --- | --- |
| 0 | — | `ffprobe` для метаданных, проверка целостности (декодирование первых и последних 2 с), проверка места на диске | `media.*`, повреждённые файлы → баннер §8 |
| 1 | «Готовим копию для анализа» | **один** вызов ffmpeg с тремя выходами: proxy 540 по короткой стороне (`h264` veryfast, CRF 26, `-g` = 1 с, CFR, теги BT.709, поворот вшит; `zscale+tonemap=hable` для HDR, без `zscale` — `colorspace`), wav 16 кГц моно, rawvideo 160×90 gray при 4 к/с в pipe → numpy | proxy, wav, кадры в память |
| 1b | (там же) | метрики кадра из pipe: резкость (дисперсия лапласиана), яркость, движение (разность кадров), тряска (фазовая корреляция) | `frames/*.npz` |
| 2 | «Слушаем речь и ищем тосты» | Silero VAD → участки речи; звуковые события YAMNet (окна 0,96 с) на всём файле; распознавание только участков речи, где нет громкой музыки; язык определяется на каждом участке (ru/ky) | `transcript_segment`, `audio_event` |
| 3 | «Находим смены сцен» | детектор сцен по кадрам 4 к/с (адаптивный порог по гистограмме и разности) + **синхронизация камер** по огибающей звука (кросс-корреляция, 100 Гц) | `scene_cut`, `media.sync_offset_us` |
| 4 | «Убираем размытые и тёмные кадры» | пороги по метрикам 1b → интервалы «плохо» и метки «чётко / темновато / трясётся» | `moment.quality_label`, интервалы-исключения |
| 5 | «Ищем танцы, аплодисменты, музыку» | построение моментов (§6) | `moment` |

Параллелизм: исполнитель анализа обрабатывает файлы конвейером. Этап 1 для файла N+1 идёт одновременно с этапом 2 для файла N; распознавание речи и ffmpeg пока не конкурируют за GPU (декодирование на CPU; вариант «декодирование на `d3d11va`, ASR на CPU» решается после S1). Одновременно работает не больше одного тяжёлого исполнителя на компьютер — несколько проектов встают в очередь.

Контрольные точки: этап на файле — единица работы. `stage_run.state=done` записывается после атомарной записи результатов. «Остановить» и перезапуск продолжают с первого незавершённого этапа файла. Каждый `stage_run` хранит `version` алгоритма: после обновления программы этап можно пересчитать выборочно.

**ETA**: скорость на секунду медиа для каждого этапа на этом компьютере (экспоненциальное среднее, хранится в `app.db`) × оставшаяся длительность. Первую оценку даём после 60 с работы, до этого — по битрейту и кодеку из ffprobe (§5.3) и профилю ПК (ядра, наличие GPU).

### 5.3 Бюджет (по S3)

**Измерено (S3, Ryzen 5 5600H, CPU, без ASR):** этап 1 + 1b — 8,1× на 1080p25 20 Мбит/с, 4,2× на 1080p50 28 Мбит/с, 3,7× на 1080p50 80 Мбит/с, 0,7× на 4K HEVC 10 бит. На 3 ч 40 мин это ≈ 27 / 52 / 59 мин / 5,3 ч. `d3d11va` медленнее CPU (0,83×), но снимает ~40 % нагрузки с процессора — кандидат на режим «ASR на CPU, декодирование на GPU», решается после S1. Первая оценка ETA — по битрейту из ffprobe: 8× (1080p ≤ 30 к/с, ≤ 25 Мбит/с), 4× (1080p50 или > 40 Мбит/с), 0,7× (4K HEVC 10 бит); после 60 с — по измеренной скорости.

**Исходная оценка (не подтвердилась):** 3 ч 40 мин 1080p H.264 с двух камер, ПК без GPU: этап 1 при скорости ~15× реального времени ≈ 15 мин; речь ≈ 40% длительности, причём звук второй камеры той же сцены не распознаём, ≈ 50 мин речи; распознавание small/turbo int8 на CPU при скорости ~5–8× ≈ 7–10 мин, параллельно этапу 1. **Итого ~20–25 мин.** С GPU — около 10 мин.

## 6. Моменты

Момент — это непрерывный интервал одного файла с типом, оценкой и объяснением. Строится правилами (`engine/moments/rules.py`), каждое правило сопровождается тестами на синтетических сигналах.

| Тип | Правило (MVP) |
| --- | --- |
| Тост | речь ≥ 25 с почти без пауз > 3 с, низкая доля музыки; дополнительные баллы, если в конце аплодисменты или музыка, а в начале или конце — ключевые слова (ru/ky: «тост», «поздравляю», «куттуктайм», «бакыт», «ден соолук», «алаверды»…) с нечётким поиском по CER |
| Танец | музыка ≥ 20 с + высокое движение в кадре; границы — по смене музыки |
| Выход молодых | всплеск аплодисментов/криков + музыка + слова ведущего («встречайте», «тосуп алалы»…) в 60 с до этого |
| Подарки | ключевые слова («подарок», «белек», «конверт», «ключи»…) в речи ведущего/гостя |
| Аплодисменты | `applause/cheer` ≥ 3 с |
| Музыка | музыка ≥ 30 с без танца (низкое движение) |

Границы: начало и конец подтягиваются к границам фраз из расшифровки и к сменам сцен в пределах ±2 с. Интервалы «плохого» кадра вырезаются из момента или опускают его оценку. Моменты с разных камер, пересекающиеся во времени события, получают общий `group_id` — это и есть «варианты с другой камеры».

Типизация намеренно локальная: экран 4 показывает фильтры с числами (Тосты 14 · Танцы 9…) ещё до того, как что-либо ушло в сеть.

## 7. План монтажа (облако)

### 7.1 Что уходит в сеть

`PlanRequest` — единственный тип, который `cloud/` умеет сериализовать:

```json
{
  "schema": 1,
  "ui_lang": "ky",
  "toi": {"kind": "wedding", "date": "2026-10-12"},
  "task": {"text": "Тосттор жана бийлер, 5 мүнөт, шайыр маанай", "duration_s": 300, "aspect": "16:9"},
  "music": [{"id": "t1", "title": "Ак куу", "duration_s": 214.0}],
  "moments": [
    {"id": "m014", "type": "toast", "t": "01:12:40", "dur": 96.4, "q": "sharp", "mark": "must",
     "text": "Урматтуу коноктор, бүгүн менин кызым…"}
  ],
  "fixed": [{"id": "m003", "pos": 0}]
}
```

Для компактности это может быть таблица TSV внутри JSON. Расшифровка тоста обрезается до ~600 символов (начало и конец), у остальных моментов — до ~160. Ожидаемый размер — 15–40 тыс. токенов на той. Никаких путей к файлам, имён файлов и метаданных устройства. Кнопка-пояснение у строки конфиденциальности показывает ровно этот JSON в читаемом виде — это честнее любой формулировки.

### 7.2 Что приходит обратно

```json
{
  "items": [
    {"moment": "m003", "in_s": 0.0, "out_s": 18.5, "audio": "music",
     "reason": {"ru": "Выход молодых под аплодисменты", "ky": "Жаштардын кол чабуу менен кириши"},
     "title": {"ru": "Айбек и Нурайым", "ky": "Айбек жана Нурайым"}}
  ],
  "reserve": ["m020", "m031"],
  "music": [{"track": "t1", "from_item": 0, "to_item": 6}]
}
```

`in_s` и `out_s` отсчитываются от начала момента. Ответ проверяется по JSON-схеме на сервере (структурированный вывод модели) и **ещё раз на клиенте**.

### 7.3 Валидатор и фиттер (`core/plan/`)

1. Выбросить неизвестные id, удалить дубли, обрезать `in/out` до границ момента.
2. Жёсткие ограничения: все `must` присутствуют (недостающие вставить по хронологии), `exclude` удалены, `fixed` стоят на своих позициях в прежнем относительном порядке.
3. Подогнать длительность к заданной с допуском ±3%: укорачивать с конца отрезки с наименьшим приоритетом по границам фраз; при нехватке — расширять в пределах момента, затем добирать из `reserve`, затем из лучших неиспользованных моментов по оценке.
4. Минимальный отрезок — 1,5 с; иначе отрезок удаляется.
5. Каждая правка фиттера добавляет локальную причину (`«Укорочено до конца фразы»`), чтобы WhyPanel оставалась честной.

### 7.4 Пересборка с новым заданием

Сохраняются отрезки с `locked` или `manual` — с их моментом, границами и относительным порядком; удалённые монтажёром моменты становятся `exclude`. В запросе они уходят как `fixed`. После ответа модели фиттер ставит их обратно и собирает остальное вокруг. Новый Timeline применяется одной командой `ApplyPlan`, поэтому откатывается одним Ctrl+Z. Перед запуском интерфейс показывает строку «Сохранятся ваши правки: 4 отрезка, 1 удалённый» — её вычисляет `core.plan.preserved_summary(timeline)`.

### 7.5 Офлайн и надёжность

Задание сохраняется в `task.state=queued`. Монитор сети при появлении связи запускает очередь, если включено «Собрать автоматически». Клиент: `POST /v1/plan-jobs` (заголовок `Idempotency-Key` = id задания) → `202 {job_id}`; затем `GET /v1/plan-jobs/{id}?wait=20` (long-poll) до результата. Повтор с экспоненциальной паузой. Если сервер уже выполнил задание, повторный POST возвращает тот же результат.

### 7.6 plan-service

FastAPI + Postgres (лицензии, устройства, учёт использования, задания с TTL 24 ч). Промпты — файлы с версией в репозитории `server/prompts/`, у ответа указывается `prompt_version`. Тексты запросов по умолчанию **не сохраняются** дольше выполнения задания; для отладки пилота — отдельное согласие в настройках. Ограничения: размер запроса ≤ 200 КБ, N планов в сутки на устройство. Модель задаётся конфигурацией сервера (по умолчанию `claude-sonnet-5-5`), поэтому её можно сменить без обновления клиента. Выбор между `claude-sonnet-5-5` и `claude-haiku-5-5` — по S4, который ещё не проведён.

## 8. Редактор

### 8.1 Модель

```python
@dataclass(frozen=True)
class Segment:
    id: str
    track: Track                 # VIDEO | MUSIC | TITLE
    media_id: str
    src_in: int                  # мкс в исходнике
    src_out: int
    moment_id: str | None
    bound_in: int                # границы, за которые нельзя тянуть (момент или трек)
    bound_out: int
    locked: bool = False
    manual: bool = False
    audio_mode: AudioMode = AudioMode.ORIGINAL
    crop_x: float = 0.5          # для 9:16
    reasons: tuple[Reason, ...] = ()
    text: str | None = None      # для титров
    anchor_id: str | None = None # титр привязан к видео-отрезку
```

`Timeline(video: tuple[Segment, ...], music: tuple[Segment, ...], titles: tuple[Segment, ...])`. Позиция на таймлайне — сумма длительностей предыдущих отрезков, она вычисляется (`timeline.starts()`) и не хранится. Поэтому пустоты невозможны. Титр задаётся смещением от начала своего видео-отрезка и «едет» вместе с ним при перетаскивании (§5 экранов).

Команды — чистые функции в `core/timeline_ops.py`: `move`, `trim`, `delete`, `split`, `replace_variant`, `set_locked`, `set_audio_mode`, `edit_title`, `apply_plan`. Каждая команда, кроме `apply_plan`, ставит `manual=True` на изменённые отрезки. `History` хранит до 200 снимков. Автосохранение после каждой команды пишет снимок в `timeline_snapshot` с задержкой 300 мс.

### 8.2 Плеер

- libmpv (LGPL, `-Dgpl=false`) через `python-mpv`, **render API**: `MpvRenderContext` + `QOpenGLWidget`, `vo=libmpv`, `render()` с `block_for_target_time=0`; на macOS — контекст GL 4.1 core. `hwdec=no` для proxy 540p: аппаратный декодер пересоздаётся на каждом отрезке EDL и роняет кадры (на Mac; на Windows `auto-safe` в чистом состоянии не сравнивали). `hr-seek=yes`, `keep-open=yes`. `wid` + `vo=gpu` — запасной вариант для Windows (S2).
- На время воспроизведения и экспорта: `NSProcessInfo` activity против App Nap (macOS), отключение power throttling и `timeBeginPeriod(1)` (Windows). В лог — `frame-drop-count` и `avsync` за сеанс воспроизведения.
- Источник — inline `edl://` со списком отрезков по **proxy**. Proxy одинаковы по кодеку, поэтому EDL играет без разрывов. Начало отрезка = pts первого кадра − 100 мкс, длина = pts(конец) − pts(начало); резы — по границам кадров исходника; пути в форме `%<байты UTF-8>%путь`. На 1 000+ отрезках — временный `.edl`-файл.
- После команды EDL пересобирается одной командой `loadfile <edl> replace start=<pos>`, позиция переводится из старых координат в новые (`timeline.map_position`). До первого нового кадра на экране остаётся старый. **На Windows пересборка 0,3–0,55 с против порога 300 мс** (S2) — причину найти в фазе 4.
- Музыкальная подложка: при изменении музыкальной дорожки ffmpeg за ~1 с рендерит `music_bed.wav` с громкостью по `audio_mode`. В mpv подключается через `audio-files`, смешение — через `lavfi-complex` (`amix`), граф только звуковой, без `[vid1]…[vo]`.
- Титры: тот же генератор ASS, что и для экспорта, подключается `sub-add`; Inter поставляется с программой и подключается через `sub-fonts-dir`, в ASS имя шрифта — `Inter`. В предпросмотре и в результате титры выглядят одинаково.
- Шкала времени, playhead и J/K/L — команды mpv (`seek`, `frame-step`, `speed`). Позиция плеера → сигнал Qt с частотой ≤ 30 Гц.

### 8.3 Таймлайн

`QGraphicsView` + собственные `QGraphicsItem`, отрисовка цветами из `tokens.py`. Отрезок < 24 px показывается без текста, с подсказкой. Ручки обрезки — по 6 px по краям. Маркер вставки — линия 2 px `garnet-500`, точка ручной правки — 6 px `track-manual`. Перетаскивание показывает раздвижку живьём, но команда применяется один раз — по отпусканию. Масштаб: от «весь клип в окне» до 1 с = 200 px.

## 9. Экспорт

1. **План чанков:** видео-дорожка режется на чанки по 30 с по границам отрезков. Длительность каждого отрезка округляется до целых кадров вывода отдельно (`round(dur × fps)`). Граница чанка — по правилу локального минимума хэша содержимого отрезка в окне ±15 с, а не жадно, чтобы правка не сдвигала соседние чанки. Длинный отрезок делится от собственного начала, страховочный рез — на 60 с (S5).
2. **Чанк** = один вызов ffmpeg: для каждого отрезка `-ss src_in -t dur -i <оригинал>` (точная перемотка при перекодировании), фильтры `fps=<fps вывода>, scale/crop(crop_x)/pad, setsar=1, format=yuv420p`, титры чанка — `subtitles=chunk.ass:fontsdir=fonts`, кодировщик с фиксированными параметрами и закрытым GOP. Имя файла — хэш входа чанка (отрезки + пресет + версия программы). Если такой файл уже есть, чанк повторно не рендерится. Ключ кэша дополнительно включает (поля титров и `crop_x` в спайке S5 не рендерились и не проверены) версию плана, версию ffmpeg, имя кодировщика (для GPU — и версию драйвера), точный текст графа фильтров, хэш ASS чанка и набор шрифтов. В графе: `fps=<fps>:start_time=0`, `tpad=stop=-1:stop_mode=clone`, `trim=end_frame=<n>`, `setpts=PTS-STARTPTS`; на выходе `-fps_mode cfr` и общий `-video_track_timescale 90000`; граф — файлом через `-/filter_complex`. Одновременно — **один ffmpeg чанка при ОЗУ < 12 ГБ** (чанк 1080p занимает 1,7–2,0 ГБ). Это даёт возобновление после обрыва, быстрый экспорт после мелкой правки и почти мгновенное «Смонтировать ещё» для пересекающихся частей.
3. **Звук** — один непрерывный проход, параллельно с чанками: `apad,atrim=end_sample=…` по тем же округлённым длительностям (без `apad` короткий звук исходника сдвигает все следующие отрезки), затухания по 10 мс на стыках против щелчков, музыка с автоматизацией громкости → `loudnorm` до −14 LUFS → WAV.
4. **Сведение:** `concat` demuxer `-c copy` для видео + WAV → AAC 192 кбит/с, `-movflags +faststart`. Звук не режется на чанки, поэтому нет ни сдвига AAC-приминга на стыках, ни рассинхрона.
5. **Кодировщики** — проверяются один раз при первом запуске тестовым кадром: `h264_nvenc` → `h264_qsv` → `h264_amf` → программный. Любая ошибка открытия GPU-кодировщика во время экспорта (в том числе `CUDA_ERROR_UNKNOWN` при нехватке памяти) — переход к следующему. ffmpeg собирается с `nv-codec-headers` 12.x: SDK 13 требует драйвер NVIDIA ≥ 610 (S5). Название видеокарты для строки «Сборка на видеокарте…» — через DXGI. Результат проверки кэшируется в `app.db`.
6. **Пресеты:** YouTube 1080p (16:9, 1920×1080, ~12 Мбит/с); Instagram Reels (9:16, 1080×1920, кадрирование `crop_x`); «Оригинальное качество» (разрешение и fps лучшего исходника, ~25 Мбит/с). Ожидаемый размер = битрейт × длительность.
7. Прогресс: `-progress pipe:1` → кадры готовых чанков. Превью текущего кадра раз в секунду — последний кадр последнего готового чанка (дёшево).

Неизвестная подстановка — ошибка сборки. Тест контраста WCAG для пар из `usage` (ink/bg-100, ink-faint/bg-100, ink-on-accent/garnet-500 и т. д.) в обеих темах. Переключение темы — `app.setStyleSheet` + перерисовка таймлайна.
- **Варианты контролов** — динамические свойства (`variant="primary"`, `chip="true"`, `badge="ready"`). После смены свойства нужно вызвать `style().unpolish/polish` — это делает хелпер `set_variant()`.
- **Обрезка текста:** `QPushButton` не умеет `elide`, поэтому нужны свои `ElidedLabel` и `ElidedButton` с подсказкой полным текстом. Политика размера — `Preferred`, фиксированной ширины у текста нет.
- **i18n:** исходные строки — на русском в `self.tr()`, перевод `ky.ts` через `pyside6-lupdate`. Все экраны реализуют `retranslate()` по `QEvent.LanguageChange`. Псевдолокаль `xx` для тестов длины. Числа и размеры форматирует `core/format.py` (запятая как десятичный разделитель, «8,4 ГБ», `01:12:40`).
- **Шрифты:** Inter и JetBrains Mono (TTF, OFL) вшиваются в программу и регистрируются через `QFontDatabase.addApplicationFont`; запасные — Segoe UI и Consolas.
- **Окно:** минимум 1280×720, ниже 1440 px ширины правая панель становится выезжающей. Один экземпляр программы (`QLocalServer`): повторный запуск и клик по уведомлению активируют уже открытое окно.
- **Уведомления:** `QSystemTrayIcon.showMessage` + `messageClicked` → открыть шаг «Задание». Прогресс на панели задач — `ITaskbarList3` (G1).
- **Без** `QGraphicsDropShadowEffect`, размытия и анимаций дольше 120 мс (README).

## 11. Сборка, поставка, лицензии

- Пакеты: `uv`, `pyproject.toml`; код-стайл — ruff; типы — mypy (strict для `core/`); тесты — pytest, pytest-qt.
- Сборка: **PyInstaller onedir** (два exe — `ToyStudio.exe` и `toystudio-worker.exe` — в одной папке) → установщик **Inno Setup** → подпись кода (Azure Trusted Signing или OV-сертификат). Nuitka — после MVP, если старт будет медленным.
- В комплекте: ffmpeg/ffprobe, libmpv-2.dll, модели (VAD, YAMNet, распознаватели речи), шрифты. Ожидаемый размер установщика — 0,8–1,5 ГБ, в зависимости от модели речи. GPU-ускорение распознавания (CUDA-библиотеки) — отдельный необязательный пакет.
- CI: GitHub Actions `windows-latest` — линтер, тесты, сборка установщика на каждый merge в main; ночной прогон eval-набора на собственном Windows-раннере с эталонным ПК.

## 12. Качество и наблюдаемость

- **Логи:** файл с ротацией в `%LOCALAPPDATA%\ToyStudio\logs`, отдельный у каждого исполнителя. Ссылка «Подробнее для поддержки» открывает «Скопировать отчёт» (код ошибки, версия, хвост лога — без текстов расшифровки).
- **Отчёты о падениях:** `faulthandler` + свой обработчик исключений → zip отчёта, отправка только по кнопке.
- **Телеметрия** (по согласию, без текста и видео): длительность этапов, ETA и факт, число правок до экспорта, время от создания проекта до экспорта, ошибки по кодам.
- **Eval-набор** (5–10 тоев с разметкой монтажёра): полнота найденных тостов ≥ 90%, медианная ошибка границы ≤ 2 с, CER ru/ky, скорость анализа на эталонном ПК, «доля отрезков плана, оставленных монтажёром без изменений» на пилоте (цель ≥ 60%).
- **Ключевая продуктовая метрика:** медиана времени работы человека от «Новый проект» до «Экспорт» ≤ 30 мин.

## 14. Открытые вопросы (к владельцу продукта)
