## Предложение владельцу продукта: бюджет анализа

Цель §1.1 «3 ч 40 мин сырья ≤ 30 мин на эталонном ПК» на CPU 5600H выполнима только для лёгкого 1080p25/30 (≈ 27 мин без распознавания речи). Обычная камера 1080p50 даёт ≈ 52–59 мин, 4K HEVC 10 бит с телефона — ≈ 5,3 ч. Узкое место — декодер исходника: proxy 360p или меньше метрик почти ничего не дают (на тяжёлой камере декодер сам по себе ~5,8× на M1).

Предлагаю заменить один порог на профиль (без учёта ASR, который пока не измерен):

| Сырьё | Цель | Сейчас (5600H, CPU) |
| --- | --- | --- |
| 1080p 25/30 к/с, ≤ 25 Мбит/с | ≤ 30 мин | ≈ 27 мин |
| 1080p 50/60 к/с, камеры до 80 Мбит/с | ≤ 60 мин | ≈ 52–59 мин |
| 4K HEVC 10 бит (телефон) | честный ETA и предупреждение до старта | ≈ 5,3 ч; рычаг — NVDEC / правильный адаптер `d3d11va`, не измерен |

Анализ идёт без участия человека (§1.1), поэтому час на тяжёлом сырье приемлем при честном ETA и уведомлении. **Требует согласия владельца**; до него в §1.1 и §13 стоит старая цель с пометкой.

## Открытые риски

- **Пересборка EDL на Windows 0,3–0,55 с** (порог 300 мс, Mac 0,07–0,12 с). Причина не найдена; гипотеза — открытие файлов при `loadfile` и антивирус. Фаза 4.
- **Вечерние потери кадров в плеере** (~29 кадров/с на ноутбуке, 4 прогона подряд) не воспроизвелись ни после нехватки памяти, ни при параллельном экспорте. В фазе 1 — писать `frame-drop-count` и `avsync` в лог.
- **Синхрон звука плеера на Windows не измерен:** в LGPL-сборке libmpv нет encoding mode. Измерен только на Mac (худший 4,4 мс).
- **Встроенная графика Intel** (OpenGL через Qt для render API) не проверена.
- **Какой GPU декодирует `d3d11va`** на ноутбуке с двумя видеокартами — неизвестно; в продукте выбирать адаптер явно.
- **Длина командной строки Windows** (32 767) в проходе звука экспорта наступит на ~250–350 отрезках — обязательная работа фазы 5 (варианты в S5).
- **Дрейф −0,148 мс/мин** в чанках 29,97 на Mac (ffmpeg 8) на Windows с ffmpeg 9 не воспроизвёлся; перепроверить на 2–3-часовом EDL с поставляемой сборкой ffmpeg.
- **Лицензия ffmpeg**: сборка с libx264 — GPL. Запуск отдельным exe; решение о GPL-сборке или LGPL без libx264 (тогда программный кодировщик — только `libopenh264`) — до фазы 5.
- **Кэш на диске:** промежуточные файлы экспорта ~0,7 ГБ на 5-минутный клип; за два дня спайков — 32 ГБ. В продукте кэш чанков с лимитом и очисткой (G7).
